# 会话模型信息持久化设计

聊天请求仍以客户端传入并经后端校验后的 `chat_model_name` 为实际执行模型。启用
会话记忆时，后端同时把该值写入 `chat_sessions.chat_model_name`；同一会话后续切换
模型会覆盖旧值，因此该字段始终表示“最近一次使用的模型”。普通和 SSE 流式接口
使用相同写入规则，避免两条请求链路产生不一致。

会话列表与历史详情均返回 `chat_model_name`。前端会把列表中的值保存在本地会话
对象中，并在打开历史会话时以详情接口返回值为准恢复模型选择器。若旧会话字段为
空，或模型已不在当前可用模型列表中，前端回退到推荐模型；推荐模型不可用时再回退
到模型列表第一项。新会话在收到流式 `done` 事件后，也立即记录本次选择的模型。

数据库初始化脚本包含新字段，增量迁移脚本负责现有部署；DAO 还保留运行时的
best-effort 列检查，以兼容尚未执行迁移的旧 Docker 数据卷。字段允许为空，因而旧
数据无需回填，API 与前端类型也都把它定义为可选值。测试覆盖首次保存、同一会话
切换模型后的覆盖更新，以及列表和单会话查询均返回最新值。
